# 小说打磨验证任务流 · Text Probe Verification

## 目标
每打磨一章后，用确定性的检查项验证是否有真正的改进，避免"表面修改"或"AI味重写"。

## 验证维度（8项探针）

### P1: 感官细节探针
- 检查是否有视觉、听觉、触觉、嗅觉、味觉的具体描写
- 关键词：cold, warm, light, dark, sound, silence, smell, taste, texture, weight, pressure
- 通过标准：每章至少5处具体感官描写

### P2: 对话个性化探针
- 检查每个角色的对话是否有独特的说话风格
- 通过标准：能通过对话内容判断出是谁在说话（不看说话人标签）

### P3: 展示而非讲述探针 (Show Don't Tell)
- 检查是否有直接解释概念的段落（"这意味着..."、"也就是说..."）
- 通过标准：核心概念通过场景/动作/对话展示，而非直接说教

### P4: 节奏控制探针
- 检查是否有长短句交替
- 检查紧张段落是否用短句，舒缓段落是否用长句
- 通过标准：至少有3处明显的节奏变化

### P5: 悬念钩子探针
- 检查每节结尾是否有钩子
- 钩子类型：未完成动作、身份反转、两难选择、神秘物品、时间限制、离奇消失、言外之意、意象钩子、回声钩子、留白钩子
- 通过标准：每章至少3个明确的悬念钩子

### P6: 不提前给答案探针
- 检查是否有直接给出最终结论的段落
- 通过标准：核心问题留到章节后半部分才揭示，前半部分只展示问题

### P7: 清除AI痕迹探针
- 检查是否有模板化表达："此外"、"然而"、"值得注意的是"、"总的来说"、"综上所述"
- 检查是否有过度解释（同一个概念解释超过2次）
- 检查是否有空泛总结（"这是一个深刻的问题"等无实质内容的句子）
- 通过标准：无模板化表达，无过度解释，无空泛总结

### P8: 修改量探针
- 用git diff统计修改行数
- 通过标准：每章修改量 > 原内容的10%（不是只改几个字）

## 验证流程
1. 打磨完成后，运行 `git diff` 查看修改内容
2. 逐项检查8个探针
3. 生成验证报告（PASS/FAIL + 具体证据）
4. 未通过的项重新打磨

## 验证报告格式
```
章节：[章节名]
修改量：[+X行 / -Y行]
P1 感官细节：PASS/FAIL - [证据]
P2 对话个性化：PASS/FAIL - [证据]
P3 展示而非讲述：PASS/FAIL - [证据]
P4 节奏控制：PASS/FAIL - [证据]
P5 悬念钩子：PASS/FAIL - [证据]
P6 不提前给答案：PASS/FAIL - [证据]
P7 清除AI痕迹：PASS/FAIL - [证据]
P8 修改量：PASS/FAIL - [证据]
综合评分：[X/8]
结论：[通过/需重新打磨]
```
